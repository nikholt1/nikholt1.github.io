Localized Streaming Service

Reason

As streaming services grew more expensive and ad-heavy, I realized that much of the content I enjoyed was already in my personal collection. This led me to question the need to rely on traditional streaming platforms. To solve this, I developed a local media server that exposed my folders for easy access across devices. Inspired by this idea, I decided to take it further and build a complete application "Refract" that enables anyone to do the same. After completing the initial server setup, I explored the Spring Boot framework, which allowed me to transform the project into a fully featured application capable of serving and managing content efficiently.

Many of my personal projects are not designed for public display, and therefore i also needed a solid project to showcase.

Backend



SQLite


The backend is written in Java using the springboot framework. Springboot together with JDBC and thymeleaf lets me easily develop a webapplication that serves data from the SQLite database through the program implementing business logic and to the frontend where the enduser is.
The program is build with a SQLite database with three tables


One table for the main_user for the login feature, seperating the main user from the users (profiles). From here i wanted to add scalability in the functionality of the videos, so i added the unfinished_movies table to be able to resume and see what has been watched. The database system follows 3rd Normal Form (3NF) since each table stores only relevant data to its own table.

So all columns are atomic, with Non-key data that depends on the entire primary key. There are no transitive dependencies between non-key columns and this ensures minimal redundancy, clear relationships and consistent movie progress tracking per profile.

The movie progress feature is not yet implemented, since i first need to be able to log in, access profiles and be able to watch the movies, since these where the core functionalities of the system.

So since the MVP first implementation is in the sprint1, the movie progress tracking per profile functionality belongs in sprint2.



The main_user stores the basic account info, username and password hash in a varchar together with the unique main_user_id.

The users table holds the users profiles that are linked to the main_user. it includes extra info like profile picture path, username and the main user that its linked to.

The unfinished_movies links the users via the user_id to the movies they have watched, with information like the video_path to fetch the actual video from the repo and how far in the video the user got before exiting the video.

The system separates accounts, user profiles and the users activity into different tables, to avoid repetition and make management easier.

The system is in 3rd normal form, because all the tables have atomic columns, all non key colums fully depend on the primary key (users, username depends on user_id, and is just part of it) and Non key columns depend only on the primary key, not on other non-key columns.

This makes the schema efficient, avoids duplicate data and prevents anomalies, wehn updating or deleting data.


Java system


Using JDBC, I can access data stored in the SQLite database. I’ve implemented a Java class called DAO (Data Access Object), whose sole purpose is to interact with the database through SQL queries.

Since the database schema is known, I only need two core models for the main functionality: MainUser for login operations and ProfileUser for profile-related data. The DAO handles the SQL queries that fetch data and build these model objects.

The repository layer acts as a central access point for fetching data, either from the DAO or from configuration files. This separation allows multiple repositories, each serving specific data needs for different controllers.

The service layer contains the business logic, handling validations and combining data as needed before passing it to the controllers.

The controllers act as the entry points of the application, mapping URL endpoints to specific methods. This setup ensures the system knows what to retrieve from the database and what to render on the Thymeleaf frontend.

With Spring Boot, I can integrate Spring Security (via a Maven dependency) to configure a custom login form and restrict access to endpoints until the user logs in as a MainUser.

Spring Boot also supports different configuration profiles (for example, application-dev.properties and application-prod.properties), allowing me to run the web application on localhost during development and on 0.0.0.0 for deployment or testing across the local network.



DevOps, DevSecOps and Code Inspection


For DevSecOps I use Github workflows to reveiw the code, using Qodana code inspection. Here i check if i have missed something in the code, if there are parts that can be refined or specified even better. After that i run a .yaml file triggered on each push, pull and merge, (this could be specified to only be on merge on pull request), where i run all the implemented unit tests and integration tests in the program. Together with the constant implementation of tests, this setup allows me to secure my code before merging it into the master branch.

For DevOps i have implemented a updater script in Java that the program utilizes once it detects that its a version behind. The program searches for the latest version online, and if its older than the newest version, it automatically executes the updater script.

For storing the versions i use Github releases to store the newest versions of the program.

This allows me to continuously integrate new features securely and push the new version to the end user. DevOps and DevSecOps also include much more than these simple implementations, such as database security and more but since the program and all its content is installed on the users platform, there is no need for me to verify data security, like if i had used a PaaS to store the database and run the webapplication.

SCRUM Agile


I worked using SCRUM sprints. Through Github projects I created a backlog with the User stories that where derived from the functionality that I wanted the system to be capable of. After creating the backlog, I made a Feasibility Study, where i concluded that the project might definitely be a "No-go" if I made the application paid for. Therefore, made the application free to use, which was intenden from the beginning. With the application being free to use and open source the program was a "GO".

After the feasibility study I made a SWOT Analysis thereafter i made a Risk Analysis which gave me a good insight in the possible strength and opportunities this project could give me, while it forced me to determine the threads and weaknesses i had as a single developer.

I worked using Github projects where i used the SCRUM Board and Issues to keep track of the progress of the project and to give me an oversight of what needed to be done, and what had been completed.

Since i had School and could not use all of my spare time on the project, i worked more SCRUM'ish than strictly after SCRUM Therefore the backlog sometimes runs up a bit, even though all of this has been one sprint. The second sprint will include more features or tweaks, but will most likely end up looking the same. Normally the backlog per sprint is frozen and cannot be touched, so i could have started a new sprint after concluding all of the features, but a lot of the backlog was updated with necessary implementations that i needed to actually make the features work.

Therefore its not strictly after SCRUM and could be called a merger of SCRUM and a planning or project-tracking service.

A lot of the time i did not have time to work on the project, so i wrote some of the things down as issues in the backlog, so that when i returned later i could simply read the issue and continue to work from there.

UI/UX


Trying to follow Shneidermans Eight Golden Rules of Interface Design, and Jacob Nielsens 10 Usability Heuristics for User Interface Design, i implemented the UI layout, and tried to rethink the application. I aimed to optimize the entire application to be as user-friendly and intuitive as possible, while also creating a visually engaging and well-designed interface. My focus was on delivering a cohesive and thoughtful UI/UX that enhances both usability and aesthetic appeal.


To achieve this, I applied Gestalt principles, a cornerstone of user experience design based on how humans naturally perceive visual information as unified, meaningful wholes rather than isolated elements. I incorporated four key Gestalt principles throughout the UI design.

See the full wireframe Here Using proximity and continuity, I carefully adjusted spacing to divide functional sections of each page. For instance, on the “Manage Users” page, I separated the “Main User” section from the “Profiles” section using deliberate spacing. I also introduced subtle spacing and grouping further down the page to intuitively suggest that additional content is available by scrolling. To enhance visual clarity, I applied similarity through color. All help-related buttons share a distinct color palette, differentiating them from functional buttons such as “Upload” or “Save”, which are found on the "add new profiles" page, while the "Delete" buttons have a vibrant red colour.

This intuitive visual cue helps users instantly distinguish between action-oriented and support-oriented elements. Finally, I used a bold, colorful divider at the bottom of each page to clearly delineate the footer. This visually signals to users that the footer contains supplementary information rather than core page functionality, maintaining both structure and visual balance across the interface.

On the Videos Browser page, the layout is structured to create a clear visual hierarchy and a sense of spaciousness through deliberate application of Gestalt principles. At the top, a minimal navigation bar contains only essential elements — Settings, Search, the Help button, and the Profile icon.

This focused arrangement leverages the law of simplicity (Prägnanz), ensuring users can easily locate core controls without distraction. Beneath the navigation, a hero section features a large, dynamic background image sourced from the assets library, accompanied by contextual text and iconography. The generous use of negative space here serves as a visual reset point, allowing users to orient themselves before diving into content. Following this, the interface transitions smoothly into structured content groupings that apply proximity and continuity.

The categories—such as Sport, Cartoon, Sci-Fi, and others—are evenly spaced and visually aligned, guiding the user’s eye horizontally while maintaining a balanced rhythm. This spacing not only reinforces intuitive scanning but also prevents cognitive overload. The “Recently Watched” section adopts the same visual grid and spacing system, using consistent image dimensions and alignment to create a cohesive flow. This repetition builds visual harmony (similarity) and reinforces familiarity, while the equal spacing subtly communicates abundance without appearing cluttered. The grid system intentionally overflows slightly beyond the visible boundary on the right, creating a visual affordance that subtly suggests horizontal scrolling or additional content beyond the viewport.

Overall, the page design balances open space and dense content areas, creating a natural rhythm that guides users from exploration to interaction — a direct reflection of Gestalt thinking in digital interface design.

Like the manage users page, this might not be the final state of the page, but merely a first layout following the principles of UI design.




Implementing the Wireframe layout with the actual webapplication


After the application is working, and i am able to fetch the data from the Springboot dependency injected Model attribute to the HTML frontend using Thymeleaf, I am able to populate the frontend with the actual data, such as the profiles, videos, categories and more.

The Model attribute lets me implement a key - value object, that i in Thymeleaf can fetch as the endpoint attaches the object that the value holds through the key.

After fetching the data from the backend i could start styling the HTML with CSS. I placed all of the styling in one main.css file containing the CSS code for the entire webapplication. The login HTML site is not able to fetch the CSS, since the whole application, including the main.css file is locked off until the user has logged in, therefore the login.html has its own style sheet.
